# DAQ 极简采集版 · 使用说明

只做三件事：**连接设备 → 采集数据 → 上传**。无登录、无回放、无任务页、无骨架解算。
体积小（无 torch/scipy/mediapipe/pyvista）、CPU 要求低（录制直接 x264、预览 15fps）。

设备：**D435 / UVC 摄像头 / USB-C 手套 / BLE 手套 / UMI 夹爪**。夹爪**只录不显**
（数据照常落盘，不做任何夹爪可视化），且**仅 Linux 包**支持 —— Windows 包里「UMI 夹爪」
组是空的（和没插 D435 时的 D435 组一样），见 [§三](#三夹爪umi--fays-s80m仅-linux-包)。

包体积（含首次自动安装的 `venv_lite`，约 750MB）：Linux 包约 **1.22GB**（含夹爪原生载荷
460MB），Windows 包约 **0.75GB**（不含载荷）。

> 与主程序共用 `data/`（录制目录、`pipeline.db`、`server_config.json`、手套序列号绑定），
> 两版可交替使用、数据互通；但虚拟环境独立（`venv_lite/`，与主程序 `venv/` 互不影响）。

## 一、启动（Windows 客户机）

```
双击 start_lite.bat
```

首次运行会自动：找 Python（没有就静默下载安装 3.12）→ 建 `venv_lite` → 装依赖
（优先 `wheels\` 离线包 → 阿里云 → 清华 → 官方源）→ 依赖自检 → 启动。之后秒开。

| 命令 | 作用 |
|---|---|
| `start_lite.bat` | 部署（按需）+ 启动 |
| `start_lite.bat reinstall` | 删除 `venv_lite` 强制重装（出问题首选） |
| `start_lite.bat help` | 打开本文档 |

**错误码**：`[错误 A]` 无 Python 且自动安装失败 → 手动装 3.12 并勾选 "Add python.exe to PATH"；
`[错误 B]`（**仅 Linux 包**）夹爪原生资源缺失 → 见 §三，多半是解压少了一层目录；
`[错误 C]` 建 venv 失败 → 磁盘空间/杀毒软件/中文路径；`[错误 D]` 依赖安装失败 → 网络或让管理员
生成离线包；`[错误 E]` 自检失败 → 杀毒软件或 `reinstall`；`[错误 F]` 启动即退 → 显卡驱动/远程桌面；
`[错误 G]` 解压层次不对 → 保持文件夹完整、不要只拷 bat。

**无外网环境**：管理员在有网机器上运行 `python scripts/pack_wheels.py --lite` 生成
`wheels\` 目录（约几百 MB），连同 `python-3.12.10-amd64.exe` 一起拷到客户项目根目录，
`start_lite.bat` 自动改走纯离线安装。

**Linux**：`./start_lite.sh`（`reinstall` / `help` 子命令同上）。Linux 包**带夹爪支持**，
启动时会多做一步夹爪原生资源自检（`[B]`），见 §三。

## 二、日常操作流程

1. **插设备**：D435（USB3）、UVC 摄像头、USB-C 手套、BLE 手套（已配对）、UMI 夹爪
   （USB3 双目 + 串口，仅 Linux 包）。约 2 秒后出现在左侧对应列表；夹爪扫描略慢
   （要经 ESP32 读序列号配对），首次「开启」还要核对/生成出厂标定。
2. **开启**：左侧设备组选中设备 → 点「开启」；中上方出现预览（RGB / 深度热力图 / UVC 可切换，
   开启设备后预览源会自动切到新开的设备）。
   - 录制必须有视频源：**先开 D435 / UVC 摄像头 / 夹爪**（只开 UVC 时以其为主视频源、无深度图；
     只开夹爪时以夹爪**左目 RGB** 为主视频源）。
   - 手套左右手按序列号/广播名 L/R 自动绑定传感器列，与主程序共用绑定记忆。
3. **录制**：填任务名（可选）→「▶ 开始」→「■ 停止」保存（「X 丢弃」作废）。
   保存后按「自动上传」开关决定是否自动入队上传。
4. **上传**：顶部填服务器地址 →「测试连接」→ 下方列表「上传全部未上传」；
   勾「上传后删除」则上传成功后自动删除本地文件。

录制数据落在 `data/recordings/`（与主程序同目录结构），在主程序的 ☁ 上传对话框同样可见。

## 三、夹爪（UMI / Fays S80M，仅 Linux 包）

夹爪在极简版里是**只录不显**：数据全部照常落盘，但不做任何夹爪可视化（双目画面、
力矩阵热力图、位姿轨迹、开合力读数都没有 —— 需要看这些请用主程序）。

**开启**：插好夹爪 → 左侧「UMI 夹爪」组里选中 → 点「开启」。最多 2 台，按开启顺序
编号；第二台的列名自动加 `gripper_2_` 前缀（同一台机器上两套数据互不串列）。
开启后窗口下方日志会打印链路就绪信息；夹爪的**左目 RGB 可当主视频源**，只开夹爪
也能录（此时 parquet 里没有深度相关列）。

**录什么**：

| 落盘位置 | 内容 |
|---|---|
| `videos/…/gripper_rgb/` | 夹爪左目 RGB 视频 |
| `observation.gripper_state` | 开合百分比 / 抓握判定 / 法向力 |
| `observation.gripper_{left,right}_force` | 三轴合力；`_force_ns` 是它的采集时刻 |
| `observation.gripper_{left,right}_force_matrix` | 10×10×3 力矩阵（整型编码，倍率见 `meta/info.json` 的 `features.*.scale`） |
| `observation.slam_trajectory` | SLAM 轨迹（8 个值一个点，时间戳单调） |

**不存**双目视频与 IMU。录制结束的日志里有一行双目丢帧汇总 —— 只录不显时，那是
判断链路是否健康的唯一证据，出问题请把它连同 `logs/` 一起发给开发。

**为什么需要 460MB**：夹爪的原生栈（`core/gripper/native/` 与 `core/gripper/sightac_sdk/`）
是**必需资源**，随 Linux 分发包下发，`start_lite.sh` 的 `[B]` 会逐项校验（7 项），
缺任何一项直接报 `[错误 B]` 并**拒启**（不会白装一遍依赖再失败）。修复办法见报错提示，
或只想要 D435/UVC/手套时跳过自检：

```bash
KSQ_GRIPPER_SKIP_CHECK=1 ./start_lite.sh    # 跳过后夹爪组为空，其它设备照常
```

**换新夹爪 / 重新读取出厂标定**：正常情况下插上新夹爪、点「开启」就会自动读取出厂
标定并连上，不用手工操作。只有换模组或怀疑标定被写坏时才需要强制重读 —— 极简版
**没有这个 UI**，用命令行（在部署目录下执行）：

```bash
cd <部署目录>
./venv_lite/bin/python tools/import_gripper_calibration.py --list        # 看已覆盖哪些序列号
./venv_lite/bin/python tools/import_gripper_calibration.py --detect      # 现场插着的这只的序列号
./venv_lite/bin/python tools/import_gripper_calibration.py --generate    # 就地为它读一份出厂标定
```

标定是**逐台**的（焦距/基线/IMU 外参各不相同），绝不能跨设备抄；旧文件会先备份成
`*.bak_<时间戳>`。跑之前先关掉正在用这只夹爪的程序（主程序或极简版窗口）。

**Windows**：不支持夹爪（原生栈是 ELF，Windows 上跑不了）。「UMI 夹爪」这一组**还在**
（五组的框一直都在，和没插 D435 时一样），但里面永远是空的、点「开启」只会提示
「列表中没有设备」—— 这是**预期**，不是故障。

## 四、与主程序的差异（本版没有的东西）

- 无登录/任务页/回放/查看器/使用向导；无骨架关键点解算（parquet 的 hand_pose 列为全零占位，合法）。
- 无独立双目相机 S80C/S80M（那是主程序的设备类型，与夹爪的「只录不显」不是一回事）；
  每类设备（D435 / UVC / USB 手套 / BLE 手套 / 夹爪）只支持 1 台（夹爪 2 台）。
- 无夹爪可视化，也没有「重新读取出厂标定」的右键菜单（改走上面的命令行）。
- UVC 摄像头采集固定 640×480、30fps（预览刷新仍限 15fps；无深度图）；
  Windows 枚举无需额外依赖（pygrabber+comtypes 可选，装了仅提升枚举质量）。
- 预览固定 640×360、15fps；编码器固定 x264（跳过 x265 速度探针，低端机友好）。
- 依赖只有 9 个包（`requirements-lite.txt`）；`imageio-ffmpeg`（77MB）提供内置 ffmpeg，
  装有系统 ffmpeg 的机器可删除该行再重装以省体积。

## 五、手工验收清单（真实设备）

- [ ] D435 出现在列表 → 开启 → RGB/深度预览切换正常 → 录 30s → 停止 → `data/recordings/<任务>/`
      出现 `videos/chunk-000/d435_rgb/`、`depth/`、`data/chunk-000/*.parquet`、`meta/info.json`
- [ ] UVC 摄像头出现在列表 → 开启（不开 D435）→ 预览切到 UVC 有画面 → 录 10s → 停止 →
      `videos/chunk-000/uvc_rgb/` 有视频，parquet 无深度相关列
- [ ] **夹爪**（Linux 包）：冷启无 `[错误 B]` → 列表出现「UMI 夹爪 (序列号)」→ 开启 → 日志有
      链路就绪 → **只开夹爪**录 60s → `videos/…/gripper_rgb/` 有视频、`observation.gripper_state`
      与 `gripper_{left,right}_force*`、`slam_trajectory` 列有值、抓握时力非零、轨迹时间戳单调
- [ ] **夹爪**：录制中拔掉夹爪 USB → 弹窗提示 + 条目录回收 + **录制不中断**（其它设备继续录）
- [ ] **夹爪**：关窗后 `ps -ef | grep -E "fayssense|ksq-camera-service|fays_vikit"` 零残留
- [ ] **夹爪**：插第二台夹爪 → 列名走 `gripper_2_*` 前缀、两条 RGB 各自成档、互不串列
- [ ] 主程序 ☁ 上传对话框能看到刚才的会话（共用 `pipeline.db`）
- [ ] USB 手套开启 → parquet 含 `observation.<列>_imu_quat/_imu_valid`，hand_pose 列全零
- [ ] BLE 手套广播名 L/R 绑定左右列正确
- [ ] 服务器地址保存后重启仍在（与主程序共用 `server_config.json`，不互相覆盖）
- [ ] 勾「自动上传」→ 录制完成后自动上传 → 服务器可见 session
- [ ] 无 Python 的 Windows 真机跑 `start_lite.bat` 全流程（含 `wheels\` 离线安装），
      确认「UMI 夹爪」组是空的（组框在、无条目）且无任何报错

## 六、常见问题

- **预览显示「无信号」**：开启设备后预览会自动切到新开设备的画面；若仍无信号，
  看窗口下方日志 —— 出现「无法打开…可能被其他程序占用」说明摄像头正被别的程序
  使用（主程序 / 浏览器 / 另一个极简版窗口），关掉它们后点「关闭」再重新「开启」。
- **录不了**：录制必须有视频源 —— 先开 D435、UVC 摄像头或夹爪。
- **「UMI 夹爪」组里是空的**：① Windows 或用了 `KSQ_GRIPPER_SKIP_CHECK=1` —— 预期行为
  （组标题还在、下拉框空、点「开启」提示「列表中没有设备」）；② Linux 上先看启动时有没有
  `[错误 B]`；③ 夹爪没插好（双目 / 串口都要通），日志里会有扫描失败的原始原因。
- **`[错误 B]` 夹爪原生资源缺失**：按提示逐项补 `core/gripper/native/`（约 460MB）——
  最常见的原因是解压时少了一层目录，或覆盖升级时只拷了代码没拷载荷。
- **夹爪开着但没数据**：日志里那条双目丢帧汇总 + `logs/` 目录是排查入口；先确认不是
  被别处的同类进程占着设备（标定/探测程序与运行中的夹爪互斥）。
- **改了代码不生效**：`start_lite.sh reinstall` 重装依赖，或先关闭所有旧窗口再重开。
